# 鱼骨图（石川图 / Ishikawa）布局规范

鱼骨图用一根脊线把多个"主因"挂在右侧的"果"上，每根主因下还可以挂子因。
本 skill 走**紧凑 spec + `fill-defaults.mjs`** 路径生成（mermaid 不支持鱼骨图）。

---

## 几何骨架

```
        ① ─┐               ③ ─┐               ⑤ ─┐               ⑦ ─┐               ⑨ ─┐
            \                 \                 \                 \                 \
             \                 \                 \                 \                 \
              \                 \                 \                 \                 \         ┌──────────┐
   ───────────●─────────●─────────●─────────●─────────●─────────●─────────●─────────●─────────► │   果     │
              /                 /                 /                 /                            │  (head)  │
             /                 /                 /                 /                            └──────────┘
            /                 /                 /                 /
        ② ─┘               ④ ─┘               ⑥ ─┘               ⑧ ─┘
```

**核心参数**（按 9 根主因 / 横 1500px 画幅举例，等比例缩放）：

| 元素 | 坐标 / 尺寸 | 备注 |
|---|---|---|
| 脊线（主箭头） | `x=80, y=430, points=[[0,0],[1280,0]]` | 横向，`endArrowhead: "arrow"` 指向头框 |
| 头框（"果"） | `x=1360, y=365, w=170, h=130` | 中心 y = 脊线 y；用 `success` 深色（`#1a5f5a` bg + 白字） |
| 上排主因框 | `y=190, h=110, w=140` | 框底 `y=300`，离脊线 130px |
| 下排主因框 | `y=560, h=110, w=140` | 框顶 `y=560`，离脊线 130px |
| 主因框间距 | 同侧 270px | 上下交替，相邻不同侧间距 135 |
| 骨线（line） | 长度（dx=100, dy=130），≈37° 倾角 | 从框中心边缘指向脊线 |

---

## 骨线连接规则

骨线（`type: "line"`，**不是** arrow）从主因框的中心边缘出发，斜接到脊线上一点：

**上排主因（指向脊线）**：
```jsonc
// 主因框：x=Bx, y=190, w=140, h=110 → 底部中心 (Bx+70, 300)
// 脊线交点：(Bx+170, 430)
{
  "type": "line",
  "x": <Bx+70>, "y": 300,
  "points": [[0, 0], [100, 130]]  // 从框底中心斜向右下到脊线
}
```

**下排主因（指向脊线）**：
```jsonc
// 主因框：x=Bx, y=560, w=140, h=110 → 顶部中心 (Bx+70, 560)
// 脊线交点：(Bx+170, 430)
{
  "type": "line",
  "x": <Bx+70>, "y": 430,
  "points": [[0, 130], [100, 0]]  // 从脊线斜向左下到框顶中心
}
```

骨线**不要**带箭头（`endArrowhead: null`），保留视觉对称感。

## 主因框排布（从左到右编号）

| 编号 | 侧 | 框位置 `x` | 骨线 `x` | 脊线交点 `x` |
|---|---|---|---|---|
| ① | 上 | 50  | 120  | 220  |
| ② | 下 | 185 | 255  | 355  |
| ③ | 上 | 320 | 390  | 490  |
| ④ | 下 | 455 | 525  | 625  |
| ⑤ | 上 | 590 | 660  | 760  |
| ⑥ | 下 | 725 | 795  | 895  |
| ⑦ | 上 | 860 | 930  | 1030 |
| ⑧ | 下 | 995 | 1065 | 1165 |
| ⑨ | 上 | 1130| 1200 | 1300 |

通项公式（第 `i` 根，从 1 开始）：
- 框 `x = 50 + (i-1) * 135`（上排时取 `i` 为奇数，下排时取偶数）
- 实际由两列交错：上排奇数 i → `x = 50 + ((i-1)/2) * 270`；下排偶数 i → `x = 185 + ((i-2)/2) * 270`
- 骨线 `x = 框x + 70`，脊线交点 `x = 骨线x + 100`

## 配色（按"流程阶段"分相）

鱼骨图主因数量多时，按**叙事色相**分组比按"语义"上色更清晰。沿脊线方向把
颜色逐步递进，让读者直觉读出"前期 → 中期 → 后期"：

| 阶段 | 推荐 bg | 语义 | 例子（开发流程鱼骨） |
|---|---|---|---|
| 起点 / 输入 | `#b8d4d4`（浅蓝绿） | input | ① 需求发现 / ② 需求分析 / ③ PRD |
| 设计 / 服务 | `#c3e0fe`（浅蓝） | service | ④ 技术选型 / ⑤ 架构设计 |
| 数据 / 实现 | `#f5ede0`（米色） | data | ⑥ 任务拆解 / ⑦ 编码实现 |
| 校验 / 决策 | `#e8c0a8`（浅橙） | decision | ⑧ 测试验证 |
| 终点 / 成功 | `#548484`（中绿）+ 白字 | success | ⑨ 收尾交付 |
| 头框（果） | `#1a5f5a`（深绿）+ 白字 | success-deep | "产品上线" / "目标达成" |

文字颜色由 `apply-styles.mjs` 自动按对比度选；走紧凑 spec 时直接在 `label.strokeColor` 里写：
- 浅色 bg → `#1e1e1e`
- 深色 bg（success / success-deep）→ `#ffffff`

## 子因（可选）

每根主因下挂 1-3 个子因点，沿主因骨线**外侧**分布：

```
       ┌────────┐
       │ ① 主因 │
       └───┬────┘
           │       ─── 子因 1
           │       ─── 子因 2
           │       ─── 子因 3
           ●───────────────► 脊线
```

实现：在主因框 `label` 字段里直接换行写子因（`text: "① 需求发现\n解决什么问题？\n给谁用？"`），
而**不**单独画子骨——视觉更紧凑，避免画面拥挤。

如果坚持画子骨，每根子骨用短 `line`（长 50-80），与主因骨线平行，间距 20-25。

## 适用场景

- **流程归因**：把一个"成果"拆成上游多个步骤（开发流程、销售流程、招聘流程）
- **问题分析**：经典 Ishikawa 用法——找一个"问题"的根因（人、机、料、法、环）
- **能力地图**：把一个目标技能拆成多个支撑能力

**不适用**：纯线性流程（用 flowchart）、有循环或回退的流程（用 flowchart 带分支）、
节点数 > 12（视觉拥挤，建议拆成两张图）。
