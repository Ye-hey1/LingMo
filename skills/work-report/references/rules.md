# 日报周报写作规则细则

## §1 事实对齐（多份日报汇总时必做）

汇总前先做四步清洗，再动笔：

**1.1 同事异名合并**
不同天对同一件事的表述常不一致，需归一。判定依据：客户单位 + 数字员工名称 + 需求数量。

真实案例：
- 7/22「党建数字员工已拆分为 3 个」
- 7/24「党委组织部(3)——未完成调研、报告」
→ 同一件事，合并为一条，主体用正式部门名「党委组织部」，括号列出 3 个子数字员工。

**1.2 状态取最新**
同一事项跨天出现，只取最后一天的状态。
例：7/22「政讯通联调中」→ 7/24「政讯通因二次调研后流程需调整，未上线」，周报写后者。

**1.3 归属过滤**
只保留【汇报主体】或【含主体的协作】条目。
- 标注【叶】→ 写"完成"
- 标注【董、叶】→ 写"与董协同完成"
- 标注【董】或其他人 → 不写入个人成果，可写入"项目整体进展"或"依赖项"
- 研发人员姓名（如【孙如】【李金】）→ 归入"研发实施支撑 / 在研跟踪"，措辞为"跟进"

**1.4 阻塞项闭环检查**
对比周初待办与周末状态，被解决的要单独成段写"阻塞项清零"，这是高价值信息，
容易被漏掉。例：OA 测试账号、企业微信接口权限、主数据对接，三项两天内清零。

**1.5 范围变更识别**
本周新出现、且不在既有项目清单内的需求，必须单独标记为"新增/增项"，
并在第六节转化为商机线索。这是从日报里能挖出的最高价值信息。

## §2 日报写法细则

**2.1 需求调研情况**
每条包含：客户单位 +（需求数量）+ 动作 + 状态 +【责任人】。
调研类工作按"调研 → 调研报告 → 需求规格说明书 → 客户签字"四阶段记录，
明确当前停在哪一阶段。

写法示例：
- `战略发展部(2)——完成需规【叶】、未完成签字【董】`
- `煤炭产业管理部(1)——完成调研【董、叶】、完成需规【叶】`

若一天内做了多部门调研，按优先级从高到低排列。

**2.2 研发实施情况**
必须按四类标签分组，并在每类末尾标数量：

```
1、【上线】xxx 1 个；
2、【联调】xxx、yyy 2 个；
3、【开发】xxx、yyy、zzz 3 个；
4、【优化】xxx，<受阻原因与新档期>。
```

未完成的要在括号里写原因，例如"（二次调研后流程需要调整）"。

**2.3 员工运行情况**
格式：`收文共收文 N 个，成功 N 个，失败 N 个。`
如非本人职责范围，日报可保留（用于项目周知），周报中删除。

**2.4 待办事项**
每条格式：`事项 —— 动作【责任人】`。
责任人是他人时，写清需要对方提供什么，不写"跟进一下"。

## §3 周报各章节写法细则

### 第一节 本周工作总览
- 长度 3-5 句，或"一句定性 + 三条产出线"结构。
- 必须出现可数成果：几份需规、几个部门调研、几个数字员工。
- 若是入职首周 / 特殊周期，第一句交代背景，但不能只写"熟悉环境"。
- 结尾一句锁定项目范围现状（如"第二阶段范围锁定为 18 个数字员工"），
  让读者知道盘子多大。

### 第二节 本周重点工作进度及成果
**按交付物分组，不按日期罗列。** 推荐四个分组：
1. 核心交付物（需规 / 方案 / 文档）—— 逐条写清客户单位、数字员工名称、覆盖范围、当前状态
2. 需求调研 —— 按部门列，写清第几次调研、明确了什么、下一步缺什么
3. 研发实施支撑 —— 联调 / 交接 / 在研跟踪 / 上线，措辞用"跟进""配合"
4. 阻塞项清零 —— 周初待办的解决情况

每个交付物条目建议格式：`客户单位 · 数字员工名称：覆盖范围说明。当前状态。`

### 第三节 客户对本周交付的评价与意见
- 按客户单位分条，每条写"客户说了什么 + 对交付节奏的影响"。
- 客户提出的反对意见、流程调整要求，必须写，这比好评有用。
- 章节末尾统一说明反馈形式：口头 / 书面。无书面确认要明写，并给出改进建议
  （建立客户确认签字台账）。
- 禁止编造评分、禁止写"客户非常满意"这类无信息量表述。

### 第四节 本周问题汇总
每条结构：**现象 + 影响 + 根因**。不在本节堆解决方案（解决方案进第五节和第七节）。
问题按影响面排序，需求返工 / 签字未闭环 / 调研预约失败 / 资源瓶颈优先。
根因要往流程和机制上归，不往个人能力上归。

### 第五节 下周核心工作计划
- 三级优先级：P0（本周必须闭环，影响交付节点）、P1（重要不紧急，有明确产出物）、
  P2（依赖他方 / 铺垫性工作）。
- 编号跨优先级连续（P0 是 1-3，P1 接 4-6，P2 接 7-9），便于会议上按号讨论。
- 每条写"动作 + 产出物"，不写"推进 xxx"。
- 第四节的每个问题，都应在第五节找到对应动作。

### 第六节 客户动态与商机线索
按五类线索扫一遍，有则写，无则不凑：
1. **增项线索**：本周新增、不在原合同/清单内的需求 → 可作范围变更或独立报价
2. **硬件与服务线索**：运行量上升、性能瓶颈、扩容评估 → 算力 / 运维服务空间
3. **横向复制线索**：同类需求出现在多个部门 → 模板化复制、标准版 + 配置打法
4. **需求纵深线索**：首期只做了一部分，后续场景可延展
5. **平台协同线索**：接口打通、账号开通降低了后续接入成本 → 二期扩容卖点

每条必须落到具体客户单位或具体需求名，禁止"客户有潜在需求"这类空线索。

### 第七节 工作复盘与业务思考
三段固定顺序：

1. **做得对的**（1 段）：给证据，不给形容词。产能数据、阻塞项清零速度都算证据。
2. **暴露的问题**（1 段）：挑本周最值得反思的一件事深挖，不铺开列。
   结尾把根因归到流程缺陷上，不归到个人。
3. **改进主张**（2-3 条，加粗小标题 + 说明）：每条必须是可执行机制，包含
   "什么节点 + 什么约束 + 谁执行"。

改进主张的三个常用方向（可复用）：
- **流程约束型**：如"需求冻结机制"——签字后才进开发排期
- **标准定义型**：如"需求颗粒度以一个可独立验收的业务闭环为拆分标准"
- **产品化沉淀型**：把重复需求抽成能力底座 + 部门配置，压缩单部门交付成本

可在末尾补一段"待补能力"，写自己的短板与补齐计划，显得真实。

## §4 常用措辞对照表

| 不要写 | 改写为 |
|--------|--------|
| 完成了很多需求调研 | 完成 4 个部门调研，输出 4 份需规 |
| 客户比较满意 | 客户认可需求收敛结果，文档内容已达成一致（口头） |
| 项目推进顺利 | 3 项周初阻塞项本周清零 |
| 有点延期 | 政讯通因二次调研后流程推翻，上线延期至下周 |
| 加强沟通 | 调研报告签字后方可进入开发排期，签字件统一归档 |
| 提升效率 | 抽出收发文能力底座，新部门交付从"调研+开发"压缩为"调研+配置" |
| 我负责了 xxx（实际是配合） | 配合 xx 完成 xxx |

## §5 结尾推断说明写法

正文结束后用分隔线加一段短说明，只讲三件事：
1. 哪些数字是我合并计算的（如"累计单量为三天日报相加"）；
2. 哪些内容我做了保守表述（如"客户评价部分无书面反馈即明写"）；
3. 可选的后续动作（导出 DOCX、压缩到一页、换成公司模板字段名）。

不超过 3 句，不复述正文内容。
